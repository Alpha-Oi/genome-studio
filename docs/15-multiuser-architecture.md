# Multi-user architecture

Этот документ описывает целевую архитектуру Genome Studio
для двух режимов работы. Сейчас в коде заложены заглушки,
реализация — отдельные фазы (см. ниже).

## Два режима работы

| Режим | Когда | Что доступно |
|-------|-------|--------------|
| **local** | Один пользователь, ноутбук | Без логина. Все проекты видны. Как сейчас |
| **multi** | Лаборатория, институт | Логин/пароль. Свои проекты + общие в организации |

Режим выбирается **один раз при первом запуске** через UI
и хранится в таблице pp_settings (одна строка).

Переключение:
- local → multi: через UI, один раз. Существующие проекты
  привязываются к первому админу.
- multi → local: только через CLI с двойным подтверждением.

## Безопасность local mode

Local mode не имеет пароля. Если запустить на сервере в интернете,
любой получит доступ к данным. Защита:
- Local слушает только 127.0.0.1.
- При попытке bind на 0.0.0.0 в local mode — отказ старта
  с требованием --unsafe-local-network.
- В UI и логе бейдж LOCAL (зелёный) / SERVER (синий).

## Ключевые точки в коде

Все эндпоинты работают через dependency get_current_user:

    from genome_studio.auth import get_current_user

    @app.get("/projects")
    async def list_all(user: User = Depends(get_current_user)):
        ...

Сейчас get_current_user всегда возвращает виртуального
LOCAL_USER (id=0, is_admin=True). После Фазы A1 та же функция
начнёт читать JWT и возвращать реального пользователя.

**Ключевое:** код эндпоинтов не меняется при переходе
local → multi. Меняется только реализация одной функции.

## Фазы

### A0 — Режимы работы (заложено сейчас)
- Модель AppSettings (пока нет — только план)
- GET /mode (реализовано, всегда local)
- Экран выбора режима (позже)
- Защита по bind-адресу (позже)

### A1 — Авторизация
- Модели: User, RefreshToken
- Хеш пароля: crypt через passlib
- JWT: access (15 мин) + refresh (30 дней)
- Эндпоинты: /auth/register, /auth/login, /auth/refresh,
  /auth/logout, /auth/me
- Экран логина/регистрации в UI
- get_current_user проверяет Authorization: Bearer
- Регистрация: по приглашению (первый — админ, он создаёт остальных)

### B — Организации и шаринг
- Модели: Organization, Membership (user_id, org_id, role)
- У проекта: owner_id, organization_id, isibility
  - private — только владелец
  - org_read — все в организации видят, правит владелец
  - org_edit — все в организации видят и правят
- UI: переключатель видимости, фильтр «Мои / Организации»

### C1 — Простая история экспериментов
- Под чатом с goal: панель «Related history»
- SQL-поиск по (gene, organism, intent) среди доступных проектов
- Показываем: «В проекте X делали knockout lacZ в E. coli,
  эффект silent, off-target 20%. [Открыть]»
- Никакого ML, работает с первого дня

### C2 — Умная история (опционально)
- Эмбеддинги goals и payloads (sentence-transformers или OpenAI)
- Косинусная близость, показываем похожие с малой лексической близостью
- Делать только если C1 окажется мало

## Что заложено сейчас (Фаза 0)
