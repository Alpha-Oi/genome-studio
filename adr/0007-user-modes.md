# ADR 0007: Два режима работы — local и multi-user

## Статус
Принято. Реализация — отдельная фаза.

## Контекст
Программу будут использовать:
- Один исследователь на своём ноутбуке.
- Лаборатория или институт — несколько пользователей,
  общие проекты, история экспериментов.

Требования разные. Один и тот же продукт должен поддерживать оба
сценария без пересборки.

## Решение
Ввести два режима работы, хранимых в БД (одна строка app_settings):

- **local** — один пользователь. Без логина. Все проекты видны.
  Слушает только 127.0.0.1.
- **multi** — несколько пользователей. Логин/пароль. Проекты
  приватные или общие внутри организации.

Режим выбирается один раз при первом запуске. Переключение
local → multi — через UI, multi → local — только через CLI.

## Обоснование
- Нет смысла заставлять одиночного исследователя заводить логин.
- Нет смысла строить multiuser-инфраструктуру, если пользователей
  всё равно не будет.
- Единая кодовая база: все эндпоинты работают через один
  get_current_user. В local он возвращает LOCAL_USER,
  в multi — читает JWT.

## Последствия
- Все эндпоинты пишутся с Depends(get_current_user) с самого начала.
- Появляется точка выбора при первом запуске.
- Local mode по умолчанию слушает только 127.0.0.1 — иначе
  любой в сети получит доступ.
- Bind на 0.0.0.0 в local mode требует явного флага
  --unsafe-local-network.
- В UI бейдж LOCAL / SERVER.
