# ADR 0008: Авторизация и организации

## Статус
Принято. Реализация — отдельная фаза.

## Контекст
В multi-режиме нужно:
- Разграничить доступ к проектам между пользователями.
- Дать возможность делиться проектами внутри организации
  (институт, лаборатория).
- Обеспечить переиспользование знаний: видеть чужие эксперименты
  в той же организации, чтобы учитывать прошлый опыт.

## Решение

### Авторизация
- Модель User: email, password_hash, name, created_at.
- Хеш пароля: bcrypt (passlib).
- JWT: access (15 мин) + refresh (30 дней).
- Регистрация по приглашению. Первый зарегистрировавшийся — админ.
- OAuth Google — опционально, позже, поверх той же модели.

### Организации
- Модель Organization: name, created_at.
- Модель Membership: user_id, org_id, role.
  Роли: owner / admin / member / viewer.
- Пользователь может состоять в нескольких организациях.
  Активная переключается в UI.

### Проекты
- Поля: owner_id, organization_id, visibility.
- visibility: private / org_read / org_edit.
  - private — только владелец.
  - org_read — все в организации видят, правит владелец.
  - org_edit — все в организации видят и правят.

## Обоснование
- Разделение user / org / project — стандарт для R&D-платформ.
- bcrypt — стандарт хеширования пароля.
- JWT с access + refresh — стандарт для API без сессий на сервере.
- Роли грубые и понятные; тонкая грануляция (per-field ACL) не нужна.

## Последствия
- Все эндпоинты /projects/* фильтруются по доступности.
- Чужие проекты возвращают 404, не 403 — не палим их существование.
- Появляется UI: организации, приглашения, переключатель видимости.
